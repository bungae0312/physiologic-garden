# 홈페이지 UX 설계

## 설계 전제: 두 종류의 방문자

| 방문자 유형 | 필요한 것 | 실패하면 |
|---|---|---|
| **저자 본인(재방문자)** | 최근에 뭘 썼는지, 원하는 노트로 최단 도달 | 탐색 마찰이 쌓여 쓰기 도구로서 신뢰를 잃음 |
| **첫 방문자** | "이게 뭐 하는 사이트인지" 3초 안에 파악 | 낯선 임상 노트 하나만 보고 이탈 |

별도 랜딩 페이지를 만들지 않고, 하나의 홈페이지 안에서 **정보 순서**로 우선순위를 나눠 해결한다.

---

## 1. 정보 습득 순서

밀도 높은 도구형 화면이라 Z-패턴이 아니라 **위→아래 F-패턴**을 전제로 순서를 짠다.

1. **상단 네비게이션** — 사이트명, ⌘K 트리거, 테마 토글. "여기가 어디인지"만 무의식적으로 각인.
2. **한 줄 프레이밍** — "물리치료와 운동학을 기록하는 개인 디지털 가든" 수준의 1~2문장. 큰 히어로 없음.
3. **큰 검색창** — 상단 네비의 ⌘K 배지와 별개로 본문 상단에 눈에 띄는 검색창. 네비 배지는 "이미 아는 사용자"용 지름길, 여기는 "검색 기능이 존재한다는 것 자체를 모르는" 첫 방문자를 위한 온보딩.
4. **시작하기 좋은 글** — `growth: evergreen`만 선별한 3개, 가로 스트립. 최근 수정 글이 지엽적일 수 있으므로 완성도 높은 진입점을 적은 공간으로 앞쪽 배치.
5. **최근 기록** — 페이지에서 가장 넓은 면적. seedling 포함 전체 노출 — "정원이 계속 자라는 중"이라는 정체성을 그대로 보여줌.
6. **주제로 둘러보기** — 카테고리 큰 블록 3~4개. 사이드바를 아직 발견 못한 방문자를 위한 대안 경로.
7. **푸터** — 노트 총 개수, 마지막 업데이트, About/RSS/Source. "살아있는 정원"이라는 신뢰 신호.

## 2. Wireframe — 데스크톱

```
┌──────────────────────────────────────────────────────────────────┐
│ physiologic                         [⌘K 검색]         [🌓]        │
├───────────────┬──────────────────────────────────────────────────┤
│               │  물리치료와 운동학을 기록하는 개인 디지털 가든.        │
│  [사이드바]     │                                                    │
│  물리치료       │  ┌──────────────────────────────────────────┐    │
│   ├ 무릎       │  │ 🔍  노트, 태그, 개념 검색…              ⌘K │    │
│   ├ 어깨       │  └──────────────────────────────────────────┘    │
│  운동학         │                                                    │
│   ├ 보행분석    │  시작하기 좋은 글                                  │
│  임상사례       │  [ 카드 ]   [ 카드 ]   [ 카드 ]                     │
│               │                                                    │
│               │  최근 기록                            [전체 보기 →]  │
│               │  ┌────────────────────────────────────────────┐   │
│               │  │ ● 운동학   전방십자인대손상 재활 프로토콜         │   │
│               │  │ 수술 후 12주까지의 단계별 부하 기준…              │   │
│               │  │ #ACL #슬관절  🌿evergreen  3일 전 수정          │   │
│               │  └────────────────────────────────────────────┘   │
│               │  (카드 반복, 세로 스크롤)                            │
│               │                                                    │
│               │  주제로 둘러보기                                   │
│               │  [ 물리치료 42 ]  [ 운동학 35 ]  [ 임상사례 18 ]      │
├───────────────┴──────────────────────────────────────────────────┤
│  노트 128개 · 마지막 업데이트 3일 전   About · RSS · Source          │
└──────────────────────────────────────────────────────────────────┘
```

**본문 폭 예외 처리**: 디자인 시스템의 "노트 본문 720px 고정" 규칙을 홈페이지는 따르지 않는다. 720px는 "읽는 최적 폭"이고 홈페이지는 "훑어보는" 페이지라 카드 2~3열이 배치될 수 있는 더 넓은 폭이 맞다. 페이지의 목적이 레이아웃을 결정한다.

---

## 3. Wireframe — 모바일 (요약)

사이드바는 드로어, 검색창은 유지(키보드 없는 환경에서 유일한 빠른 탐색 수단), 시작하기 좋은 글은 가로 스와이프, 최근 기록은 1열 세로.

---

## 4. 섹션 → 대상 → 근거

| 섹션 | 주 대상 | 차지 공간 | 근거 |
|---|---|---|---|
| 프레이밍 한 줄 | 첫 방문자 | 최소 | 설명은 필요하되 콘텐츠보다 우선하면 안 됨 |
| 큰 검색창 | 양쪽, 특히 온보딩 | 작음 | 키보드 우선 원칙의 존재를 학습시키는 지점 |
| 시작하기 좋은 글 | 첫 방문자 | 작음 | evergreen 필터로 첫인상 품질 보장 |
| 최근 기록 | 재방문자 | 가장 큼 | Digital Garden 정체성(계속 자란다) |
| 주제로 둘러보기 | 첫 방문자 | 중간 | 사이드바 발견 못한 사용자용 대안 경로 |
| 푸터 | 양쪽 | 최소 | 정량적 신뢰 신호 |

---

## 5. 의도적으로 넣지 않은 것

- 큰 마케팅 히어로 이미지/문단 — 도구이지 제품 소개 페이지가 아님
- 자동 재생 캐러셀/슬라이더 — 모션은 상태를 설명해야지 장식이면 안 됨
- 로그인 기반 "이어보기"/개인화 추천 — 정적 생성 기반이라 세션/계정 전제 없음. 필요하면 브라우저 로컬 상태가 한계(즐겨찾기 정도가 그 예외 사례, 06번 문서 참고)
- 태그 클라우드 섹션 — `/tags` 페이지와 사이드바에 이미 있는 정보의 세 번째 반복
