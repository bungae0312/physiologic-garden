# Sidebar UX 설계

## 0. 문제 정의

폴더 트리, 태그, 최근, 즐겨찾기, 검색, 테마, 내비게이션, 브레드크럼까지 280px 폭 하나에 모두 담아야 한다. 전부 동시에 펼쳐놓으면 절제된 밀도 원칙이 무너지므로 계층을 나눈다.

| 그룹 | 항목 | 특징 |
|---|---|---|
| 고정 계층(Persistent) | Search 진입점, Theme, Collapse | 어떤 모드든 항상 같은 자리 |
| 전환 계층(Switchable) | 폴더구조/Navigation, Tag, Recent, Favorites | 한 번에 하나만 표시 — 탭 전환 |

Breadcrumb은 이 두 그룹 어디에도 속하지 않는다(9번 참고).

---

## 1. 전환 계층 스위처

사이드바 상단에 가로 세그먼트 탭 4개(폴더/태그/최근/★). 클릭 시 아래 스크롤 영역 콘텐츠만 교체. 기본 활성 탭은 **폴더**. 마지막으로 봤던 탭은 다음 방문에도 유지.

---

## 2. 폴더 구조 & Navigation

`content/notes/` 폴더 구조를 그대로 렌더링한 결과물 — 별도 관리 메뉴가 아니다. 새 폴더 = 코드 변경 없이 트리에 즉시 반영.

- 폴더 아이콘 없음 — 들여쓰기 + 펼침/접힘 화살표만
- 폴더 옆 노트 개수 배지(`물리치료 (42)`)
- **현재 노트로 이어지는 경로는 페이지 로드 시 자동 펼침 + 좌측 악센트 바 강조**
- 폴더는 가나다순, 노트는 제목순 정렬

---

## 3. Tag 모드

`_meta/tags.yaml` 기반, **사용 빈도순 정렬**. 태그가 많아질 걸 전제로 상단에 인라인 필터 입력. 클릭 시 `/tags/[tag]`로 이동(사이드바 안에서 목록을 펼치지 않음 — 트리 모드와 동일한 단순함 원칙).

---

## 4. Recent 모드

홈페이지 "최근 기록"과 같은 데이터, 사이드바 폭에 맞춰 제목+상대시간만 표시. 최대 15~20개, 이상은 "더 보기"로 홈페이지 전체 피드 연결.

---

## 5. Favorites 모드

**설계 배경**: 홈페이지 설계에서 "로그인 기반 개인화는 넣지 않는다"고 했지만, 그때 남겨둔 예외가 정확히 이것 — 브라우저 로컬 상태 한도 내의 개인 북마크.

- 노트 상세 페이지 메타 정보 행에 ★ 토글 아이콘 추가(Article Layout에 대한 추가 요구사항)
- `growth: evergreen`(객관적 성숙도)과 다른 축 — "자주 참조하는 나만의 앵커 노트"라는 주관적 신호
- 빈 상태: "노트 상세 페이지의 ★ 아이콘으로 추가하세요" 안내로 대체

---

## 6. Search

사이드바 최상단(탭보다 위, 고정)에 검색창처럼 생긴 **버튼**. 클릭 시 전역 `⌘K` 팔레트가 열림 — 인라인 검색 로직을 따로 만들지 않음. 사이드바 검색 버튼 / 홈페이지 큰 검색창 / 상단 네비 ⌘K 배지는 **같은 팔레트를 여는 세 개의 진입점**.

---

## 7. Theme

사이드바 최하단 고정 유틸리티 행에 아이콘 토글(라이트/다크/시스템 순환). 스크롤 영역 바깥에 항상 고정.

---

## 8. Collapse

| 상태 | 트리거 | 동작 |
|---|---|---|
| 전체 펼침(데스크톱 기본, ≥1280px) | 기본값 | 280px, 라벨·탭·트리 모두 표시 |
| 아이콘 레일(태블릿 자동/데스크톱 수동) | 헤더 `«` 버튼 또는 화면폭 | 56px, 탭 4개 대신 "펼치기" 아이콘 하나만 |
| 완전히 숨김(모바일, <768px) | 상단 햄버거 | 오버레이 드로어, 노트 선택/바깥 탭 시 자동 닫힘 |

아이콘 레일에서 4개 탭을 다 욱여넣지 않고 단일 버튼으로 단순화 — 좁은 폭에서 기능을 다 유지하려는 욕심을 버림.

---

## 9. Breadcrumb과 사이드바의 관계

Breadcrumb은 사이드바 컴포넌트가 아니라 콘텐츠 영역, 노트 제목 바로 위에 위치.

- 사이드바 트리의 자동 펼침/강조 = "전체 지도 안에서 내 위치" (탐색용)
- Breadcrumb = "지금 읽는 글이 속한 경로" (맥락용, 콘텐츠에 종속)

같은 정보를 좁은 폭에 두 번 넣는 중복을 피하고, 탐색용/맥락용으로 역할을 나눠 각자의 자리에 배치. 브레드크럼 클릭 시 사이드바의 해당 폴더도 함께 펼쳐지고 강조되어 동기화 유지.

---

## 10. 상태 유지(Persistence)

로컬 스토리지에 유지해야 하는 것: 마지막 활성 탭, 폴더 트리 펼침/접힘 상태, 사이드바 폭 상태(수동 선택), 즐겨찾기 목록.

**이유**: 매 방문마다 트리를 처음부터 다시 펼쳐야 한다면 저자 본인이 매일 쓰는 도구로서 마찰이 누적됨.

---

## Wireframe

**전체 펼침 · 폴더 모드**
```
┌─────────────────────────────┐
│ physiologic             «   │
├─────────────────────────────┤
│ 🔍  검색…               ⌘K  │
├─────────────────────────────┤
│ [폴더] 태그  최근  ★         │
├─────────────────────────────┤
│ ▾ 물리치료 (42)              │
│    ▾ 무릎 (12)               │
│      ● 전방십자인대손상 재활   │
│        반월판손상 보존적치료    │
│    ▸ 어깨 (9)                │
│ ▸ 운동학 (35)                │
│ ▸ 임상사례 (18)               │
│ ▸ 참고문헌 (7)                │
├─────────────────────────────┤
│ 🌓 테마                      │
└─────────────────────────────┘
```
