# MDX 파이프라인 설계 — Zero-Friction Authoring

## 핵심 설계 원칙

> **"저자는 글을 쓰고 저장하는 것 외에 아무것도 하지 않는다. 나머지는 시스템이 파일 경로와 본문 자체에서 추론한다."**

원본(콘텐츠) vs 파생(카테고리·태그인덱스·검색인덱스·TOC·연관글)의 분리를, "저자가 손대야 하는 필드를 최소화하는 방향"으로 끝까지 밀어붙인다.

---

## 1. 자동화 항목별 매핑표

| 자동화 | 저자가 하는 일 | 도출 근거(원본) | 파생 로직 | 산출물 | 소비처 |
|---|---|---|---|---|---|
| 카테고리 생성 | 폴더에 파일 저장 | 파일 경로 | 경로 세그먼트를 카테고리 트리로 채택 | 카테고리 트리 | 사이드바, 브레드크럼, 카테고리 페이지 |
| 태그 생성 | frontmatter `tags:` 작성 | frontmatter | 전체 스캔 → tag→notes 역인덱스, `tags.yaml`과 대조(미등록시 경고만) | 태그 인덱스 + 리포트 | `/tags`, Tag 컴포넌트 |
| 검색 등록 | (없음) | plain text + frontmatter | draft 아닌 모든 노트 자동 포함 | search-index.json | SearchPalette |
| TOC 생성 | 헤딩 작성(평소 글쓰기) | 마크다운 헤딩 | id 부여 + heading 트리 추출 | heading 트리 | TableOfContents |
| Related Post 생성 | (없음) / `related:`로 오버라이드 | 태그 교집합+카테고리+백링크 그래프 | 가중치 스코어링 상위 N개 | related-notes 맵 | RelatedNotes |

---

## 2. 2단계 파이프라인

파일 단위로 독립 계산 가능한 것과 전체 노트가 모여야 계산 가능한 것을 구분한다.

```
[Phase 1] 파일 단위 변환 (캐시/병렬 가능)
   ├─ frontmatter 파싱 + 스키마 검증
   ├─ 경로 → 카테고리 세그먼트 도출
   ├─ 마크다운 → 헤딩 트리 추출
   ├─ 위키링크 파싱 → 아웃바운드 링크 목록
   └─ plain text 추출
        │
        ▼ (전체 노트가 모인 뒤)
[Phase 2] 컬렉션 전역 집계
   ├─ 태그 인덱스 집계
   ├─ 아웃바운드 링크 역전 → 백링크 그래프
   ├─ Related Post 스코어링
   ├─ 검색 인덱스 최종 조립
   └─ 미등록 태그 / 깨진 링크 리포트
```

**이유**: 백링크와 Related Post는 본질적으로 전역 정보라 파일 하나만 봐서는 계산 불가능. Phase 1은 파일별 캐시(mtime/hash)로 재처리 최소화, Phase 2는 가벼운 메모리 연산이라 매번 전체 재실행해도 무방 — 노트 수에 비례해 빌드가 느려지지 않도록.

---

## 3. 카테고리 자동 생성

frontmatter에 category 필드 없음 — 파일 경로가 유일한 원본. 카테고리 페이지는 Phase 2에서 유니크 경로 집합을 뽑아 `generateStaticParams`로 생성. 새 폴더 = 코드 변경 없이 새 카테고리 페이지.

---

## 4. 태그 생성/등록 — 하이브리드 모드

- 엄격 모드(미등록시 빌드 실패)는 저작 흐름을 끊음
- 완전 자유 모드는 taxonomy 붕괴(무릎/슬관절/knee 난립)

**채택**: 태그는 즉시 사용 가능(빌드 차단 없음), Phase 2에서 미등록 태그를 리포트로 수집(경고만), `scripts/`가 주기적으로 감사(audit).

---

## 5. 검색 자동 등록

"등록"이라는 행위 자체가 없음. Phase 2에서 draft 아닌 전체 노트를 무조건 스캔해 매번 새로 조립. `draft: true`만 검색/sitemap에서 제외.

---

## 6. TOC 자동 생성

저자가 `##`/`###`로 소제목을 나누는 것 자체가 TOC 생성 행위. Phase 1에서 헤딩마다 id 부여 + 레벨/텍스트/id 트리 저장. 컴포넌트는 런타임 재파싱 없이 그대로 렌더링. 헤딩 2개 미만이면 TOC 생략.

---

## 7. Related Post 자동 생성

**스코어링 신호(가중치 순)**: ① 백링크 그래프상 직접 연결(가장 강함, 저자의 명시적 의도) → ② 공유 태그 개수 → ③ 같은 카테고리 여부(약한 보조 신호).

**수동 오버라이드**: `related:` 필드로 슬러그 직접 지정 가능하지만 필수 아님. 값 있으면 우선, 없으면 자동 계산 폴백.

---

## 8. Frontmatter 최소화 스펙

| 필드 | 필수 여부 | 없을 때 기본 동작 |
|---|---|---|
| `title` | **필수(유일)** | — |
| `tags` | 선택 | 빈 배열 |
| `description` | 선택 | 본문 첫 문단 자동 추출 |
| `growth` | 선택 | 기본값 `seedling` |
| `related` | 선택 | 자동 스코어링 결과로 대체 |
| `draft` | 선택 | 기본값 `false` |
| `category`/`slug`/날짜 | 필드 자체 없음 | 경로·git 로그에서 자동 도출 |

이론상 저자는 `title` 하나만 쓰고 본문을 채우면 카테고리·검색·TOC·연관글까지 전부 동작.

---

## 9. 빌드 실패 vs 경고

| 조건 | 처리 |
|---|---|
| frontmatter 타입 오류 | 빌드 실패 |
| 슬러그 충돌 | 빌드 실패 |
| 미등록 태그 | 경고만, 통과 |
| 깨진 위키링크 | 경고 + "예정된 노트" 렌더링, 통과 |
| 헤딩 없는 짧은 노트 | 정상, TOC만 생략 |
| references 없는 임상 노트 | 경고 없음(권장일 뿐) |

**이유**: "구조를 깨뜨리는 것"(스키마, 슬러그 충돌)만 막고 "아직 완성되지 않은 것"은 성장 과정으로 허용.
