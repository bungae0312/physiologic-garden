# Article Page UX 설계

## 설계 전제

Article 페이지는 정원에서 유일하게 "한 편의 글로서 완결되는" 화면이면서, 동시에 전체 지식 그래프로 다시 흩어지는 분기점이다. 두 개의 임무를 순서대로 수행한다 — ① 이 글을 온전히 읽게 하는 것, ② 다 읽으면 정원의 나머지로 자연스럽게 이어주는 것.

```
① 상단(브레드크럼·제목·메타)
② 본문 + TOC (읽기 임무 — 방해요소 최소화)
────────────── 읽기가 끝나는 경계선 ──────────────
③ Tags → ④ Reference → ⑤ Related(백링크+추천) → ⑥ Previous/Next  (이어주는 임무)
```

---

## 1. 상단 (브레드크럼 · 제목 · 메타데이터)

```
물리치료 › 무릎 › 전방십자인대손상 재활 프로토콜

전방십자인대손상 재활 프로토콜
🏷 운동학  🌿 evergreen  · 3일 전 수정 · 읽기 8분      ★
```

| 요소 | 넣는 이유 |
|---|---|
| 브레드크럼 | 사이드바 설계의 "맥락용" 위치 정보 |
| 제목 | 글의 정체성 |
| 카테고리 배지 | 저카디널리티라 색으로 즉시 구분 |
| 성장 배지 | 독자의 기대치를 미리 조정(seedling이면 짧고 미완성일 수 있음을 예고) |
| 최종 수정일 | git 로그 자동 산출. 최신성이 곧 정확성인 도메인이라 창작일보다 크게 노출 |
| 읽기 시간 | 지금 읽을 시간이 있는지 판단 근거 |
| ★ 즐겨찾기 | 사이드바 설계에서 예고한 개인 유틸리티, 가장 가벼운 시각적 무게 |

---

## 2. 본문 (Body)

- 최대 폭 720px(이 페이지가 유일하게 "읽는 페이지")
- 위키링크는 점선 밑줄 → hover 시 실선
- **Citation 마커**: 문장 끝에 붙는 작은 위첨자 각주 번호(예: `[^1]`). 기존 remark-gfm의 GFM 각주 문법을 재사용 — 새 커스텀 문법을 만들지 않음
- Callout의 "Quote" 타입(문헌 발췌, 블록 단위)과 Citation 마커(문장 근거 표시, 인라인)는 용도가 다른 별개 도구로 공존

---

## 3. TOC

우측 sticky 컬럼, 스크롤에 따라 현재 섹션 자동 하이라이트. 긴 임상 노트에서 전체를 다 읽지 않고 필요한 섹션으로 바로 점프 가능해야 함 — "참조하는 도구"라는 정체성과 직결. 헤딩 2개 미만이면 렌더링 안 함. 모바일은 제목 아래 접이식 목차로 전환.

---

## 4. Tags

```
#ACL  #슬관절  #재활프로토콜  #스포츠손상
```

본문을 다 읽은 직후 재확인·재탐색용. 클릭 시 `/tags/[tag]`로 이동 — Related 섹션으로 넘어가는 다리 역할.

---

## 5. Reference (참고문헌)

```
참고문헌
[1] Kisner C, Colby LA. Therapeutic Exercise. 8th ed. 2022.        ↑
[2] Wright RW et al. ACL reconstruction rehabilitation. JAAOS. 2015. ↑
```

원칙 7(임상적 신뢰감)의 직접적 실현. `references` frontmatter(구조화 데이터)에 저장해 본문 각주 번호와 인덱스로 매칭. 구조화해두는 이유: 향후 전역 참고문헌 색인 페이지, AI 근거 인용에 재사용 가능. 각 항목에 본문 복귀용 `↑` 백링크. `references` 필드 없으면 섹션 자체 생략.

---

## 6. Related — 백링크와 추천을 구분

```
이 노트를 참조하는 노트                    ← 명시적 연결
  반월판손상 보존적치료
  스포츠손상 복귀 기준

비슷한 주제의 노트                         ← 암묵적 추천
  회전근개 파열 재활 프로토콜
  무릎 관절가동범위 정상치
```

- **백링크**(위): 저자가 실제로 `[[ ]]`로 연결한 가장 신뢰도 높은 관계 — 강조된 스타일
- **자동 추천**(아래): 태그+카테고리 기반 스코어링 추정치 — 가벼운 스타일

두 그룹을 합치지 않는 이유: 독자가 "저자의 의도적 연결인지, 시스템의 추측인지" 구분해야 신뢰도가 유지됨. 빈 상태는 "아직 이 노트를 참조하는 글이 없습니다 — 정원이 자라면서 연결이 생길 거예요"로 성장 지향적으로 표현.

---

## 7. Previous / Next — 시간순이 아니라 "같은 폴더의 형제 노트"

```
← 반월판손상 보존적치료          무릎 카테고리          스포츠손상 복귀 기준 →
```

일반 블로그의 발행 시간순 Previous/Next는 "발행일 중심 선형 목록이 아니다"라는 아키텍처 원칙과 충돌한다. 그래서 **같은 폴더(카테고리) 안의 형제 노트를 사이드바 트리와 동일한 정렬(가나다순)로** 보여준다 — "다음에 읽어야 할 순서"가 아니라 "같은 주제를 계속 둘러보고 싶다면 여기"라는 편의 기능.

- 라벨에 소속 카테고리명을 명시해 순서가 아닌 맥락임을 분명히 함
- 페이지에서 가장 낮은 시각적 비중
- 형제 노트가 없으면 섹션 자체 생략(비활성화 화살표 대신 존재를 지움)

## 9. 조건부 렌더링 정리

| 섹션 | 데이터가 없을 때 |
|---|---|
| TOC | 헤딩 2개 미만이면 렌더링 안 함 |
| Reference | frontmatter `references` 없으면 섹션 생략 |
| Related – 백링크 | 없으면 성장 지향적 안내 문구 |
| Related – 추천 | 태그/카테고리 겹침 없으면 섹션 생략 |
| Previous/Next | 같은 폴더에 형제 노트 없으면 섹션 생략 |
